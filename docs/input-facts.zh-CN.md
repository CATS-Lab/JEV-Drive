# 结构化输入修正：v1.4

[English](input-facts.md) | 简体中文

输入从原始地图读取客观事实，JEV 仍自行作出驾驶决策。v1.4 修复了中间 VectorMap 转换时遗漏的属性，未引入 GT 中间轨迹或自动安全接管。

| 输入 | 来源与语义 |
|---|---|
| `road.lanes[].attributes` | 原始 `lane.parquet` 的用途、允许车型、转向/汇入/分叉类别、地图终点属性和限速原值。`lane_direction` 是源动作类别，车道行驶朝向仍由中心线点序定义。 |
| `left_boundary/right_boundary.source_samples` | 源边界顶点的坐标、样式和颜色，与几何对应；不把沿线变化压成单一虚线或实线。`type` 为源属性一致值或 `mixed`。 |
| `road.road_boundaries` | 独立道路外缘（v1.3 加入），区别于车道分界线。 |
| `road.map_areas` | 人行横道、安全岛、导流区域、缓冲区域、路口和路面标记，保留源类别、关联车道与裁剪标志。非法多边形不修造，ID 单独报告。 |
| 交通控制的车道关联 | 依据关联两侧的实际实体 ID 解析，修正 `LIGHT_TO_LANE` 的方向读取错误，同时补齐标志和停止线关联；标志保留源朝向。空占位记录不是信号灯。 |
| 自车横向运动 | 增加横向速度、横向加速度与运动来源；不再让模型只凭纵向速度解释横向相对运动。 |
| `observation_scope` | 说明对象 ROI、最近 K 筛选、候选/保留数量、被 K 限制遗漏的数量、速度语义和包围盒参考点。未列出的空间不代表已确认无障碍。 |

道路级导航排除源数据标记的 `SHOULDER_LANE`；因缺少乘员资格信息，也排除 `HOV_LANE`。其他车道仍展示原始用途和车辆限制，模型需要结合事实判断。这样不会再把已知路肩当成普通导航车道候选。

限速保留源字符串 `speed_limit`，`speed_limit_unit` 为 `unverified`，`speed_limit_mps` 为 `null`。尚无经过核实的单位定义，不能擅自换算；`0` 也不能当成已知的 0 m/s 限速。配置的 `max_target_speed_mps` 是控制上限，不是道路限速。动态信号灯相位缺失时继续返回 `unknown`，车道关联修复并不会产生实时灯色。

区域来自原始 `location` 多边形并裁剪到 ROI，保留洞与多片几何。不能把所有区域都解释成不可通行：人行横道、路口和安全岛用途不同。标线采样来自源顶点，不由距离或邻接关系猜测法律许可。

模块分别位于 `integration/map_facts.py`、`state/lane_attributes.py`、`state/map_areas.py`、`state/observation_scope.py`，便于独立调试。历史 v1.2 rollout 缺少这些事实，也缺少独立道路外缘；其图示可能把路肩一并编号为“车道”，不能当成四条普通行车道。本次修复未调用 API 重跑。

连续相同样式/颜色的标线注释仅保留该段首尾源采样点，保留每个属性变化两侧的位置；道路几何仍由边界 `segments` 提供。这是注释压缩，不是把弯曲车道拉直。新增字段会增加输入体积；离线字符数不等于模型 token 数，API 上下文容量尚未用新输入实测。
